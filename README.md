# Futari Labs site

The Futari Labs website. An immersive 3D site built with React, TypeScript, three.js, and GSAP.

The site is one scroll journey in four chapters: the bridge, Futari Engineering, Kensaku, and a particle installation with links. `docs/journey.md` describes the sequence and how the transitions work.

## Run it

Requirements: Node.js 22.18 or later, pnpm 10, and Google Chrome for the capture tools.

```sh
pnpm install
pnpm dev          # dev server with hot reload
pnpm build        # typecheck, then production build to dist/
pnpm preview      # serve dist/ at http://localhost:4173
pnpm lint
```

Add `?still` to the URL to skip the entrance and hold one fixed frame. Add `?probe` to record frame intervals for `tools/perf.mjs`.

## Regenerate the assets

The bridge and the landscape are generated by code. No modeling application is needed.

```sh
pnpm assets:build
```

The command takes about 18 seconds and rewrites every file in `public/assets/`. The output is deterministic.

| To change | Edit |
| --- | --- |
| Bridge shape, segments, joints, chips | `tools/assets/bridge.ts` |
| Landscape: platform, foreground ridge, mountains | `tools/assets/terrain-fn.ts` |
| The two exhibits, their enclosures, and the installation base | `tools/assets/exhibits.ts` |
| What gets baked into each vertex, and the particle targets | `tools/assets/build.ts` |

## Capture and check

Start `pnpm preview` first.

```sh
node tools/capture.mjs docs/journey                 # rest frame of every chapter, desktop and phone
node tools/capture.mjs public/fallback --bare       # the same without text, for the no-WebGL fallback
node tools/journey-test.mjs                         # functional checks
```

Regenerate `public/fallback/` after any visual change. `docs/journey.md` lists the other tools.
